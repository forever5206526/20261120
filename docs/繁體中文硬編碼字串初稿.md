# 繁體中文硬編碼字串翻譯初稿

檢查對象：2026-01-07_Ragexe_1767686776_VHL_clientinfo_fixed.exe  
原始對照：WARP Inputs/Translations_EN.yml  
目前狀態：**已建立 8 項 CP950 十六進位候選映射；唯讀驗證通過；尚未套用至 EXE。**

## 1. 翻譯內容

| WARP 原始項目 | 繁體中文候選 | 格式參數 |
|---|---|---|
| Deletion Time - Part 2 | %d年%d月%d日 %d:%d:%d | 保留 6 個 %d |
| Message Box | 訊息 | 無 |
| Total in Cash Shop | 總計：%d Cash | 保留 1 個 %d；為符合原字串空間，未加「商城」 |
| Pet Evolution item amount | %d個 | 保留 1 個 %d |
| Tip box - Part 2 | 離開 | 無 |
| Equipment - Dismount Cart | 卸下手推車 | 無 |
| No Color | 無色 | 無 |
| Rune Tablet - Rune List | %s的符文 | 保留 1 個 %s |

## 2. 已建立的映射檔

`localization/Translations_zhTW.yml`

檔案使用 UTF-8 儲存映射結構，`find`／`replace` 的內容以十六進位形式表示；替換字串的位元組使用 Windows-950／CP950。WARP `TranslateClient` 對尖括號包住的十六進位字串會呼叫 `Exe.SetHex()`，因此不會把中文字當作預設 ASCII 文字寫入。

## 3. 唯讀驗證結果

- 8 個搜尋模式在原始 EXE 中都唯一命中。
- 8 個 CP950 替換字串都保留原有 `%d`／`%s` 格式參數。
- WARP 會在替換資料後附加 NUL；8 項都能放入原字串後方連續的零填充區，未跨越下一個非零位元組。
- 「總計：%d Cash」替換為 13 bytes，連同結尾 NUL 共 14 bytes；目前可用容量為 16 bytes。
- 已建立 `tools/validate_zhTW_translations.py`，可對指定 EXE 重跑搜尋唯一性、CP950 位元組長度、零填充容量及格式參數檢查。

完整偏移、可用容量與 SHA-256 請見：
- `docs/繁體中文CP950與字型相容性.md`
- `reports/zhTW_translation_validation_2026-11-20.json`

## 4. 重要限制

1. 這是硬編碼字串的第一批候選翻譯，不代表整個客戶端已繁體中文化。
2. 尚未由 WARP 實際執行 `TranslateClient`，也沒有產生修補後 EXE。
3. `CustomCodePage=950` 的靜態前置條件已找到，但 WARP 讀取的 `Exe.BuildDate` 是否符合 `>= 20250716` 尚待確認。
4. 字型是否含完整繁體中文字形、UI 是否截字、NPC 對話及輸入法是否正常，仍需完整客戶端素材及 Windows 實機測試。

本階段沒有修改原始 EXE。
